# XReactor Handoff — beta-v136 Naechste Schritte

Stand: 2026-06-23

## Aktueller Befund

RT node-52 hat laut UI und Log inzwischen einen besseren Zustand als vorher:

- RT laeuft.
- Reaktor ist sichtbar.
- 25 Turbinen-Geraete sind sichtbar.
- Kapazitaet ist gelernt beziehungsweise gelockt.
- RT wartet auf Auftrag.
- Es wird kein Sollwert vom Master angezeigt.

Damit ist das bisherige Learning-Problem nicht mehr der wahrscheinlichste Hauptblocker.

## Nicht anfassen

Der User hat ausdruecklich gesagt, dass der RT-UI-Punkt aktuell nicht gemacht werden soll. Daher keine Arbeit an der lokalen RT-UI-Anzeige fuer Turbinenzaehlung oder Darstellung, solange das nicht erneut freigegeben wird.

## Naechster Untersuchungsblock

Jetzt geht es um Master zu RT:

1. Master pruefen: Warum bekommt node-52 keinen Auftrag?
2. RT Status pruefen: Meldet RT Kapazitaet und Modus korrekt an Master?
3. Master rt_sync pruefen: Nutzt Master die RT-Kapazitaet und setzt daraus Assignment und Setpoint?

## Wichtiger Codepfad

RT Status-Payload:

- xreactor/nodes/rt/status_snapshot.lua
- meldet capacity_ready, capacity_max und capacity_source.

Master Planung:

- xreactor/master/rt_sync.lua
- nimmt RT-Kapazitaet nur als nutzbar, wenn capacity_ready true ist.
- nimmt eine RT-Node nur als steuerbar, wenn der Mode aus Master-Sicht MASTER ist.

## Vermutung nach Screenshot

Der Screenshot zeigte oben den Modus AUTO. Wenn Master diesen Zustand ebenfalls als AUTO oder AUTONOM sieht, wird die Node wahrscheinlich als nicht steuerbar eingestuft. Dann gibt es keinen Auftrag, obwohl Kapazitaet gelernt ist.

## Was fehlt

Im hochgeladenen ZIP war nur:

- rt/node-52.log

Es war kein Master-Log enthalten. Fuer den naechsten Diagnose-Schritt wird ein Master-Log gebraucht.

## Wonach im Master-Log gesucht werden soll

Suchbegriffe:

- node-52
- RT
- mode
- controllable
- assignment
- SET_SETPOINTS
- STATE_REQUEST
- MODE_APPLY
- capacity_ready
- capacity_max

## Moeglicher kleiner Diagnose-Patch

Falls kein Master-Log verfuegbar ist, waere ein kleiner Diagnose-Patch im Master sinnvoll. Ziel waere ein Log pro RT-Planungsrunde mit:

- node id
- gemeldeter Mode
- capacity_ready
- capacity_max
- controllable true oder false
- reason
- berechneter power_target_percent

Wichtig: Dieser Diagnose-Patch soll nur sichtbar machen, warum node-52 keinen Auftrag bekommt. Er soll keine Steuerlogik veraendern.
